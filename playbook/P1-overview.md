# Phase 1 — Overview — `/brd-p1-overview`

**Follow:** `P0-phase-rules.md` · **Closes with:** APPROVED · **Output:** `brd/P1-overview.md`

(Not to be confused with the Summary BRD, phase 8C.)

## Purpose
Starting from the approved BRD name and summary, describe the area plainly with everything the memory knows inside the fence, so everyone agrees what the BRD is about before going deeper.

## Produce
1. **What this area is:** a short narrative, building on the summary's What and Why, in plain English.
2. **Who uses it:** users, teams and downstream consumers (summary's Who, plus what the memory shows: report readers, groups with access, document owners).
3. **Main data and flows:** the key entities and the main flows of the core as a ```flow block, with the jobs and procedures behind them.
4. **Key facts:** volumes, frequencies, systems involved (```figures where the memory or a quick data check has numbers).
5. **Coverage:** what the memory knows well inside the fence and where it is thin.
6. **Questions** about purpose and users (`### Q-…`), including any summary part still "not known yet".

## Review page
The overview with labels on every statement; template sections fed; coverage; questions.
